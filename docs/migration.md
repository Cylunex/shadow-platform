# OIDC 直接改造手册

本文适用于尚未接入统一登录的现有项目。目标是一次切换到原生 OIDC，不保留旧登录入口，
也不建设 Forward Auth 或 Hybrid 兼容层。仓库中的地址和账号均为示例。

## 1. 改造边界

本批只改人类登录：

- 业务数据、业务权限和内部用户 ID 保持不变；
- Agent、MCP、移动同步和定时任务继续使用独立 Bearer；
- 媒体、LLM 和数据迁移拆到后续批次；
- 切换后旧登录路由、旧 Cookie 和旧密码不再被接受。

不要在同一上线窗口同时迁移认证、数据库、对象存储和主域名。

## 2. Phase 0：盘点与备份

在改代码前记录：

1. 当前登录、退出、会话中间件和权限检查入口；
2. 浏览器页面、机器 API、回调、探活和静态资源路径；
3. 用户表中可保留的业务用户 ID，以及新 `(issuer, subject)` 映射位置；
4. Nginx、应用配置、数据库和服务管理配置的备份；
5. 规范入口、精确 callback、post-logout URI 和最小准入组。

测试数据和测试账号不得复用真实用户内容。

## 3. Phase 1：应用原生 OIDC 改造

在未接生产流量的版本中完成：

- 登录入口生成 `state`、nonce 和 PKCE；
- callback 完整校验并交换 Token；
- `(issuer, subject)` 到内部用户的映射；
- 应用自己的服务端会话与 Cookie；
- 仅本站退出和全局退出；
- 浏览器未登录返回登录跳转，机器 API 返回 JSON 401/403；
- `/healthz` 与 `/readyz` 分离；
- 删除对客户端 `Remote-*` 身份头的信任。

旧登录代码不需要与 OIDC 并存。为了可回滚，保留上一个完整发布制品和数据库备份即可。

## 4. Phase 2：Identity 登记与预发布验证

为应用创建独立 client，登记精确 URI 和准入组。client secret 只放服务器受限文件，生产
配置不进入 Git。

在隔离的预发布入口完成：

- 正常登录、拒绝无权限账号、退出和会话过期；
- state、nonce、PKCE、issuer、audience 和签名负向测试；
- 子路径 URL、Cookie Path、WebView 跳转和返回键；
- 机器 Bearer、后台任务和 webhook 无回归；
- Identity 不可用、JWKS 刷新失败和时钟偏差场景。

预发布不通过就不切生产，不在生产临时保留两套登录兜底。

## 5. Phase 3：一次切换

选择低流量窗口：

1. 备份当前配置并记录旧发布版本；
2. 部署 OIDC 版本但暂不放入公网流量；
3. 执行数据库迁移，仅新增身份映射，不改业务资源所有权；
4. 配置规范入口证书和反向代理，别名只做 308；
5. 切换流量并使旧 Cookie、旧登录路由失效；
6. 立即执行关键验收，不通过则整体回滚。

切换完成后不再给旧密码登录留隐藏入口，也不通过 Nginx 注入身份头绕过应用 OIDC。

## 6. 生产验收门槛

| 类别 | 必须通过 |
|---|---|
| 登录 | 正常账号登录、返回原路径、刷新后会话仍有效 |
| 拒绝 | 无准入组、篡改 state/nonce、错误 issuer/audience 均失败 |
| Cookie | Secure、HttpOnly、SameSite、host-only 和 Path 正确 |
| 机器调用 | 缺 Bearer 为 401，正确 Bearer 协议不变且不发生 302 |
| 路由 | 规范入口可用，别名只 308，静态资源和 callback 无前缀错误 |
| 运维 | healthz、readyz、日志脱敏、证书续期和服务重启正常 |

验收证据只保存状态码、时间、配置哈希和脱敏关联 ID，不保存账号、Token 或实际域名。

## 7. 回滚

回滚是恢复整个旧发布，不是让两套认证长期共存：

1. 停止放量；
2. 恢复上一个应用制品和 Nginx 配置；
3. 回滚仅新增且确认无新数据依赖的身份迁移；否则保留表结构但停止使用；
4. 验证旧版本关键路径；
5. 修复后重新走预发布与一次切换。

不要在故障时扩大可信代理、公开应用端口或把 client secret 临时写入配置仓库。

## 8. 项目顺序

- Garden：公开页面保持匿名，管理入口在应用内启动 OIDC；
- Stock：页面直接改原生 OIDC，MCP、Agent 和任务保留 Bearer；
- Travel：从首版使用原生 OIDC、Media 和项目内资源权限；
- 其他新项目：直接按 `docs/app-integration.md`，不再评估旧登录兼容。

Health 已完成的 Forward Auth / Hybrid 保持现状，不纳入后续项目的技术选型。
